# 见微视觉测振仪：代码审查与状态机说明

日期：2026/10/21。审查对象为本工程 `06_软件与FPGA` 的实际源码；对照 `10_构思与技术路线_20261021` 的 FPGA 核心建议方案，以及现有两板开发资料和协议 V1。结论区分当前实现、此次修正、仍待实现或验证的内容。

## 1. 结论

现有代码已经形成“载板控制 PL＋Linux 主程序＋Nano 外设协处理”的基础闭环。NFC 选测点、软件单 ROI 测量、结果保存、按保存记录打印、补光与打印互斥、前面板、语音和网络服务的职责划分基本合理。

但它还不是“FPGA 为主要计算核心”的视觉测振实现。现有位移跟踪、去趋势、频谱和结果判决均在 PS/Linux，当前 PL 实现的是外设、事件时间戳、PWM、WS2812、按键/编码器和看门狗。PL 视觉位移核、双目深度流水线和背景补偿尚未实现；显示用的降采样、时间带通与欧拉运动放大已有逐位验证的 PL RTL，但未接入厂家视频工程（见 `FPGA视觉处理方案_20261021.md`）。当前代码可以作为整机控制底座和 PS 算法参考实现，不能据此宣称 FPGA 测振主链已经完成。

此次已实际修正控制、判级、记录归属和仿真中的具体问题，并增加回归测试。修正后仍有下文列出的实现缺口和硬件验证事项，不能把主机测试、RTL 行为仿真等同于上板验收。

## 2. 尚未闭环的主要问题

| 优先级 | 问题与证据 | 对技术路线的影响与下一步 |
|---|---|---|

| P1 | 标定文件目前只核对 `id/mm_per_px/axis`，没有绑定分辨率、镜头、焦距、工作面和相机模式 | 读到正的比例值并不代表它适用于当前画面。现已阻止未标定像素误用毫米阈值；已加载但不适用的标定仍需增加适用性校验和标定流程。当前 mm 结果仍需实物标定验收。 |
| P1 | `printer.status_query` 默认 `none`，按行数和等待时间估计结束；`dle_eot` 无应答时仍可能走成功分支 | 数据发送完和等待结束均不能证明纸张完整打印。需取得该批次 EM5820H 的真实波特率、CTS 极性、缺纸状态和完成确认方式，实测后固定策略。当前打印路径属于待上板确认的实现。 |

| P2 | Nano 只有 Wi-Fi/NTP、NFC、SD 语音和 UART 协议；未见 MQTT、测量文件上传或远程看板实现 | 网络连通不等于远程测量平台已经完成。Nano MicroSD 当前服务于 WAV 语音，没有直接接收 AX 的波形存储命令；Linux 测量记录保存在 AX 本地文件系统。 |

P1 表示会影响核心路线、数据真实性或上板闭环，P2 表示功能或验收仍不完整。这里没有把建议中的全部功能算作既定实现，也没有把队友可能保存在其他路径的算法算入本次审查结果。

## 4. Linux 主控逻辑

### 4.1 启动与并发模型

`Application::init` 在启动线程之前阻塞 SIGINT/SIGTERM，交给 signalfd 处理；随后加载标定、按 AXI 地址发现设备、初始化 TCA/INA/RTC、配置 PL、建立 Nano 链路，启动传感器、打印机、相机及 UI。

主线程用 epoll 和定时器处理控制命令与服务调度。20 ms 周期排空 PL 事件并维护 Nano 链路，100 ms 更新测量/五灯/报警，200 ms 读取功率和维护 PL 时钟映射，1 s 执行风扇/转速/重连等慢任务。传感器、相机、打印机和 UI 各有线程。设备缺失时允许保留软件功能，所以 `init_done=true` 只表示应用初始化结束，不能理解为所有硬件通过自检。

### 4.2 测量状态机

| 状态/触发 | 条件与动作 | 后续 |
|---|---|---|
| stopped | 相机未成功启动；主循环每 5 s 尝试启动 | 成功进入 preview |
| preview → measure_start | 无掉电/关机、没有测量/打印作业、相机可用；冻结测点、照明和 UTC/单调时钟映射；可自动开补光并暂停风扇 | 原子占用 capture，避免待启动请求被覆盖 |
| capturing 首帧 | 固定纹理模板，选择 ROI；纹理不足或越界返回 `roi_not_trackable` | 无效结果/回 preview |
| capturing 后续帧 | 每帧做局部 NCC 搜索和亚像素峰值插值，记录帧号、时间、位移、分数及边缘/饱和指标 | 达到时长或 measure_stop 后 analyzing |
| analyzing | 检查完整性和质量；合格后才轻微均匀重采样、去趋势、Hann 频谱、统计 | 返回完成回调，再 preview |
| 相机连续 10 次取帧失败 | 500 ms 单次取帧等待下约 5 s；取消当前记录并返回 `camera_timeout`，不无限占用测量状态 | 等待相机恢复；恢复前拒绝新测量 |
| cancel / PFAIL / shutdown | 取消优先于待启动请求；取消即使无新帧也生效；应用 generation 拒绝迟到回调 | 不提交已经取消的记录 |

已固定的质量门限：时间戳必须来自有效采集时钟并严格递增，帧序号连续；丢帧、低 NCC/失败帧、非有限位移、搜索到边界、图像饱和均使本次结果无效；采样间隔相对平均值偏差超过 10% 时返回 `irregular_sampling`。该 10% 是当前软件完整性门限，仍需结合目标频带和相机实测确定误差界限。

修正前会跨丢帧/低质量帧插值，且边缘命中和饱和只计数、不拦截。现在保留可用的原始位移用于诊断，但不会把补出来的序列作为合格计量。V4L2 只能给出 dequeue 到达时刻时仍可预览，但不会因此得到有效测量。

当前没有振动峰显著性/SNR 判据；静止目标的有限噪声也可能选出一个频谱峰。因此软件输出的“主频”仍需加入噪声底/峰可信度验证，不能仅凭频谱最大 bin 判定存在该频率振动。

### 4.3 记录、判级和报警

本次记录使用开始测量时的测点 ID/名称/NFC UID；中途换卡或 `set_point` 只影响之后的测量。采集开始的单调时钟映射到开始时冻结的 UTC 基准，避免计算完成时间或中途校时污染起始时间。自动补光关闭之后，记录仍保存本次开始时的照明状态。

合格结果：若有有效比例，位移转为 mm 后按毫米峰峰值阈值判级；没有比例则保留 px，显示“未判级”，不触发毫米报警。无效结果也为“未判级”，不会把先前有效的红/黄报警清成正常。系统初始状态为未判级，外置塔灯和 HL105 不会提前亮绿色。

正常/预警/报警分别驱动绿/黄/红；预警短鸣 300 ms，报警按 1 s 周期鸣响前 500 ms。短按 K1 仅静音、停止当前语音，不清除灯光等级；下一次合格、有标定的测量会重新按结果设置等级和声音。

保存路径为 `records_dir/<measurement_id>`，主文件 `record.json`，并有 `waveform.csv`、`spectrum.csv`；有采样数据时保存 `imu.csv`、`reference_adxl345.csv`。打印从已保存记录生成。注意辅助传感器 CSV 的存在尚不证明参考数据质量或同步已经通过验收。

### 4.4 打印状态机与互锁

```text
idle → 读取已保存记录 → 预算/互斥检查、关闭补光
     → 满足最短断电时间 → power_on → 等待模块启动
     → open_uart → wait_ready(CTS) → comm_on
     → 分条带发送 ESC/POS → drain → wait_finish
     → comm_off → 关闭UART → power_off → idle
```

测量和打印互斥；打印时拒绝开补光。打印线程的预检查只读原子状态和状态快照，不再同步等待可能已经停止的主事件循环。串口写入每轮检查 abort，背压时可以取消。PFAIL/关机在 BoardService 中锁定打印机电源和通信输出，和打印线程写操作串行，防止关断后再次被打开。

`wait_finish` 的默认分支仍是估时，硬件完成确认尚未闭环。供电为用户确认的 12 V EM5820H，程序不会把它作为 Nano 的外设。

### 4.5 掉电、关机与前面板

PFAIL 低：PL 锁存关闭 PWM；Linux 停止测量/新打印/记录提交，取消打印并关载板负载。PFAIL 连续高 1 s 后才恢复允许状态；恢复不会自动重放打印或重新开始测量。

长按 K1 默认 3 s 请求关机：拒绝新业务、取消测量、关闭补光和负载，向 Nano 发 PREPARE_POWER_OFF，等待答复或超时；等待打印线程结束后停相机并 sync，设置 `shutdown_prepared=true`。该字段只表示应用准备工作完成。默认随后调用 Linux poweroff；禁用系统关机时明确提示 Linux 仍在运行。它不等于系统已卸载文件系统，也没有硬件自动切断总 12 V。SIGTERM 则走有序服务退出。

EC11 按 x4 电气计数转换为默认每档 2 计数；旋转改变显示缩放，编码器短按复位显示缩放，长按不额外触发短按。五灯：HL101 系统，HL102 网络，HL103 测量，HL104 外设/短事件，HL105 最近一次有效判级。

## 5. Nano 控制逻辑

| 状态机 | 主要状态与规则 |
|---|---|
| 协议会话 | 无会话 → HELLO 建立会话；换会话停止旧语音。32 条请求缓存；同 seq/同请求重放响应，不重复执行；冲突返回 SEQ_CONFLICT。旧会话事件通过 boot_id 和 event_id 区分。 |
| 事件队列 | 32 项，单项最多 384 字节；未 ACK 时 IRQ 持续高。主动推送一次，AX 可 DRAIN 补取，连续前缀 ACK 后出队。满队列丢最旧事件并计数，不能保证长期断线期间事件不丢失。 |
| Wi-Fi | OFF / CONNECTING / CONNECTED / WAIT_RETRY；连接超时默认 20 s，重试退避 5 s 到 120 s；连接后启动 NTP。空 SSID 表示关闭连接。 |
| PN532 | INIT → IDLE → RF_SETTLE → WAIT_LIST → 关闭 RF/等待下一轮；错误重试/重新初始化。相同 UID 持续存在不重复发卡事件，连续缺卡后发移除事件。只读 UID 选测点，不是身份认证或测量算法。 |
| SD | SD_CD 消抖 300 ms，插入后挂载，失败 5 s 重试；只读语音资源和卡信息。准备断电时禁止挂载并尝试卸载。 |
| 语音作业 | QUEUED → PLAYING → DONE / STOPPED / FAILED；队列最多 4 项，历史 32 项；job_id 在历史范围内去重。音频独立 FreeRTOS 任务，PCM16 转左右声道一致的 I2S32，功放先静音再使能，结束后静音关功放。 |
| 电源 | PFAIL ISR 立即关功放并锁定；任务和 ISR 使用同一临界区保护，播放任务不能在掉电边沿之后重新开功放；高电平稳定 1 s 才解除。PREPARE_POWER_OFF 锁定并停止音频。 |

UART 默认 115200，RTS/CTS 打开；100 MHz AXI UART16550 高速档应两端统一 781250。PN532 使用 Mode 0/LSB first，SD 使用自己的 SPI 事务设置；两者共用 Nano SPI，通过各自 CS 与 U601 门控 MISO。实际线序、电平、流控和 SPI 共享资格仍需首板验证。

语音停止和 SD 卸载有有限等待时间；拔卡、I2S 超时与 PREPARE_POWER_OFF 同时发生时的资源释放仍需硬件故障注入测试。编译成功不能替代这些验证。

## 6. PL 状态机与寄存器

| 模块 | 控制逻辑 |
|---|---|
| AXI4-Lite | 独立暂存 AW 和 W，均到达后提交，BVALID 保持至应答；读地址锁存、固定读等待，RDATA 在背压时保持。已修复状态寄存器的 WSTRB，零字节使能不产生副作用。 |
| 时间与事件 | 64 位 FCLK 计数；读低字锁存高字；各源边沿先存 pending 时间，再仲裁进入 512 项 FIFO；IRQ 为非空电平。存在溢出/丢弃计数，但 Linux 当前没有把它完整接入辅助数据质量判决。 |
| 按键/编码器 | 同步、消抖、长按单次事件；编码器只允许单比特 Gray 转换，非法双跳计错误，输出步进方向。 |
| PWM | 周期边界装载占空比；软件使能；PFAIL 和看门狗 kill 锁存；原因解除后还需 W1C 才能清锁存。 |
| WS2812 | IDLE → BIT → RESET → IDLE；每帧锁存颜色，5 灯 GRB/MSB，0/1 高电平 320/640 ns，总位周期 1270 ns，复位低电平至少 300 us；忙时 SEND 以 pending 合并请求。 |
| 看门狗 | Linux 周期喂狗；超时关闭补光并发送 HL101 红色故障帧。正常退出主动停用看门狗，避免退出后误报。 |

当前 RTL 的行为仿真通过不表示 Vivado 模块引用、IOBUF 顶层位置、约束、时序、资源和目标器件实现已经通过。`bd/add_carrier.tcl` 必须在实际厂家摄像头工程里执行并检查输出映射，不能把 Tcl 文件本身当作已生成的设计。

屏幕、触屏与编码器的当前操作规则见同目录 `UI与触屏编码器说明_20261021.md`。UI 的灰色按钮命中已与绘图可用条件统一，关机页显示主控实际状态，触屏静音与 K1 共用处理。

## 9. 下一阶段执行顺序

1. 把两板控制底座接入队友已经能出图的厂家 Vivado 工程：固定 FPGA part、摄像头模式、视频/VDMA/DDR 通路、Linux 可见接口和 PL 帧时刻。先跑无视觉加速的 PS 参考链并记录基线。
2. 固定单 ROI 测量契约：原始灰度、帧号、采样时刻、配置编号；输出 dx/dy、质量、失败码和周期数。用当前 PS 跟踪器与合成/实拍序列建立黄金数据集，先决定算法与误差目标，再写对应 PL 位移核。
3. 实现 PL 核并完成定点误差、边界、丢帧、持续流量、背压测试。接 AXI-Stream/DMA，PS 继续负责标定、结果/频谱、UI、记录和打印。比较相同输入的 PS/PL 速度、端到端延迟、CPU、丢帧、资源和时序。
4. 增加背景 ROI、多测点和辅助传感器 FIFO。完成样本对时和延迟标定之后，再做相机运动补偿与加速度计交叉验证。
5. 显示放大支路（空间低通与降采样 → 时间带通与增益/限幅 → 上采样重建）已有 PS 实现和逐位一致的 PL RTL，界面保留原图/放大并排；它不参与定量位移换算。接入时按 Z7010 实际 BRAM/DSP 预算确定工作分辨率和缓冲方式。

这一顺序能让 FPGA 的作用落在持续视频流、位移乘加/插值与确定性时序上，同时保留现有 PS 软件作为可复现的对照。放大展示链已具备，下一步应优先完成帧时间戳和位移核，再扩展展示功能。
