# FPGA 视觉处理：现状、接入与待定事项

日期：2026/10/21。对象为 `ax7010/pl/vision`、`src/measure/vision.cpp`、`pc_sim`。结论先行：显示用的图像处理链（金字塔降采样、时间带通、欧拉运动放大、振动能量图）已有 PL 实现，与 PS 参考实现、PC 模型逐位一致，并用电脑摄像头实拍数据验证；尚未综合、未接入厂家视频工程、未上板。测振位移的 PL 化还没开始，建议作为下一步。

整机职责及目标边界以[PL、PS 与 ESP32 分工](../../00_当前设计方案/PL_PS_ESP32职责与接口分工.md)为准。位移提取优先于显示增强；亚像素拟合初期留 PS、最终迁入 PL，背景补偿和 FFT 留 PS。下列结构是已有显示增强 RTL 的实现，不代表已经与双目 BM、载板控制和待实现的位移核同时装入器件。

## 1. 已实现的处理链

| 步骤 | 定点规格 |
|---|---|
| 降采样 REDUCE | 每轴 [1 4 6 4 1]/16，边界复制，保留偶数行列，`(和 + 128) >> 8`。全分辨率反复减半到宽度不超过 200 的工作图 G0（640×480→160×120，1280×720→160×90） |
| 金字塔 | G1 = REDUCE(G0)，G2 = REDUCE(G1)，拉普拉斯带 L1 = G1 − EXPAND(G2) |
| 上采样 EXPAND | 每轴偶数点 (a+6b+c)、奇数点 4(b+c)，`(和 + 32) >> 6`（向下取整），饱和到 int16 |
| 时间带通 | 每个 L1 像素两个一阶低通，状态 Q6 int16：`s += (coef·(x−s) + 32768) >> 16`；带通 = 高截止低通 − 低截止低通。系数 `round(65536·(1−exp(−2πf/fs)))` 由 PS 按实测帧率算好写入 |
| 放大 | delta = clamp((增益·带通 + 32) >> 6, ±96)，放大画面 = clamp(G0 + EXPAND(delta), 0, 255) |
| 振动能量 | amp += (|带通| − amp) >> 4（约 16 帧滑动平均，Q6）；PS 按帧最大值（至少 2 灰度满量程）映射成伪彩 |

拉普拉斯带去掉了局部均值，整体亮度变化（灯光闪烁、自动曝光）在能量图里大部分被抵消；定点低通对常值输入有几个 Q6 单位的死区，静止画面的带通残留不超过 3/64 灰度。

三套实现：`vision.cpp`（PS 软件，vibmond 内独立线程，测量采集期间暂停）、`pc_sim/vision_model.py`（PC 模型）、`ax7010/pl/vision/rtl`（`vp_reduce.v` 流式降采样、`vp_core.v` 帧级处理）。

## 3. PL 结构与资源估算

`vp_reduce` 为流式模块：每拍最多一个像素、无反压、4 行行缓存，输入宽度须为偶数，奇数高度在帧后补出最后一行（需要约 w/2 拍空闲）。`vp_core` 在帧到达时写 G0/G1/G2 乒乓缓存；帧结束后阶段 B 逐带通像素 13 拍、阶段 C 逐 G0 像素 11 拍，放大结果原位写回 G0。

| 工作图 | 片内存储（BRAM36，器件共 60） | 每帧处理（100 MHz） |
|---|---|---|
| 160×120（640×480 输入） | 约 27：G0 双缓冲 10、状态 7.5、G1/G2 4、delta 1.5、行缓存 4 | 2.7 ms |
| 160×90（1280×720 输入） | 约 22：G0 双缓冲 8、状态 6、其余 8 | 2.1 ms |

乘法器约 4 个 DSP48（两个系数乘、增益乘、地址乘）。LUT/FF 需综合后给出。BRAM 是主要约束：G0 双缓冲占三分之一以上。可选的削减办法见第 6 节。

## 4. 接入方式（建议）

视觉核拟以只读旁路接在相机的 AXI4-Stream 视频上：只在 tvalid 且 tready 时取像素，旁路不向源施加反压；必须保证内部缓存能接收输入，不能保证时须显式标记溢出/丢帧。像素格式、Y 字节位置、旁路点时钟和 CDC 均待实际工程确认。已收到队友 DVP/AXIS/VDMA/DDR 工程，但 Linux V4L2 通路尚未建立，不能把它视为已有接口。

PS 通过 AXI-Lite 写系数、增益、尺寸，读状态；放大画面和能量图经地址窗口读取（约 2×19 KB/帧，界面 8 帧/秒刷新时约 0.3 MB/s）；每帧完成给一个中断。帧起始脉冲接入 carrier_ctrl 事件 FIFO 作为新事件源，用同一个 64 位计数器给帧打时间戳，替代 V4L2 出队时间——这同时解决测量记录的采样时刻证据问题。PS 侧在 `VisionLive.backend` 填 "PL"，界面显示处理端和每帧耗时。

## 5. 建议从 PS 迁移的部分

| 优先级 | 内容 | 理由 |
|---|---|---|
| 1 | 相机帧起始时间戳进事件 FIFO | 改动小；直接提升计量可信度 |
| 2 | 位移核：把 `NccTracker` 的整数搜索（ZNCC 的 Σp、Σp²、Σp·t）搬到 PL，先一个目标 + 一个背景，再按资源扩展多测点；亚像素拟合初期留 PS、验证后迁入 PL，背景补偿/标定/FFT 留 PS | 图像搜索计算重复，适合硬件化；PL 与 PS 基准用同一输入核对。LK 为后续比较选项，不预设其精度优于已验证方案 |
| 3 | 预览缩放复用 `vp_reduce` | PS 不再逐帧缩放整幅图 |
| 已完成 | 降采样、时间带通、运动放大、振动能量 | 待接入 |
| 不迁移 | 频谱、统计、标定、判级、界面、记录、打印 | 数据率低，PS 足够，改动和验证成本高于收益 |

## 6. 需要决定的事项

1. **相机工程接入**：已收到[队友 Vivado/裸机工程](../../11_队友Vivado工程_20261021/工程接收与衔接核对.md)，需要确认旁路点、时钟、像素格式、分辨率、帧率和 Linux 管理的视频通路；尚未导出当前 XSA 或上板复测。
2. **资源预算**：队友保存报告约 88% LUT、39.5 个 BRAM36；本显示链估算另需 22 个 BRAM36，直接叠加已超 60 个总量，尚未含位移核。先保障位移与采样，按实际测量需要保留 BM，再评估显示增强；各项须以合并后综合结果确认。缩减双缓冲、使用 DDR 等只是待评估实现选项，不能当作已实现的资源节省。
3. **位移核算法**：先与当前 PS 基准一致地实现 ZNCC 整数搜索，再验证亚像素并迁入 PL；LK 只在实测误差、质量和资源比较后考虑。
4. **综合估算**：是否允许在 WSL 安装开源综合工具 yosys（apt 安装，约几十 MB），在接入厂家工程之前先拿到 LUT/FF/DSP/BRAM 数字。

## 7. 像素亮度时序分析

已纳入：振动能量图就是每个像素亮度时间序列的带通能量。小位移时亮度变化约等于局部灰度梯度乘以位移，所以它能指出“哪里在振、在什么频带振”，但幅值混合了纹理对比度，不能直接换成毫米；平坦区域没有信号，灯光闪烁和自动曝光会带来非运动的亮度变化（拉普拉斯带已抵消大部分整体变化）。PC 实验台另有“主频分布”（每像素 128 帧 FFT 的峰值频率）和“像素亮度时序探针”，用于判断这一思路在实际场景中的效果。硬件上做逐像素完整 FFT 需要缓存上百帧，不建议；若需要主频分布，可在 PL 用少数几个频点的滤波器组实现。

## 8. 电脑上的仿真流程

见 `pc_sim/README.md`：`webcam_lab.py` 用电脑摄像头实时运行位精确模型；`check_bitexact.py` 比对 Python 与 C++；`run_rtl.py` 在 WSL 的 Icarus Verilog 中跑 RTL 并与模型逐位比对。新增 PL 模块按同一流程先写模型、再写 RTL、用实拍帧比对。
