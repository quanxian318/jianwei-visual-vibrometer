# 测振算法推进：LK 位移核、背景参考、全视场谱线与 PL 累加核

日期：2026/10/21。按 技术路线建议稿 §4（PL 位移核）、§8（频谱与质量）、§10 阶段 2–3，以及 [PL、PS 与 ESP32 职责和接口分工](../../03_设计说明/PL_PS_ESP32职责与接口分工.md) 推进。用户两段视频用于仿真；**电机 620 rpm（10.33 Hz）没有作为算法输入**，只在结果出来后用于比对。没有上板，没有 Vivado 综合，没有 ARM 交叉编译。

## 结论

1. **位移核选型：平移逆组合 LK（投影外光度不变形式）**，定点化后与 PL 累加核逐位一致。合成亚像素平移（32×32 模板、41 帧斜坡＋正弦）上，LK 误差 RMS 0.005 px（无噪声）/ 0.014 px（σ=2 灰度噪声），现有 NCC 抛物线插值为 0.13 px，LK 约好 10–25 倍。在用户视频的电机外壳测点上，两者位移曲线一致；LK 对窗口内含两种运动（板边＋背景/阴影）的测点会给出"位移计算不稳定"，比 NCC 更严格。
2. **两段视频都没有测到转频处的面内位移**。视频一：用全视场谱线检出的 11.134 Hz 去查各测点位移谱，幅值 0.02–0.05 px，与该频段噪声中位数之比只有 0.9–1.8；视频二手持旋转/透视明显，所有板件测点都被质量门限拒绝。所有"有效"位移结果的主频都在 0.5–1.2 Hz，是相机/手持低频运动，不是振动。
3. **全视场亮度谱线（盲检，不给先验）找到了转频**。视频一最强谱线 **11.134 Hz**，另两条 7.728 Hz、3.421 Hz 正好是 2 倍、3 倍频在 30 fps 下的混叠位置（|2×11.134−30|=7.73，|3×11.134−30|=3.40），算法自动标为谐波，判为有效。视频二最强线 10.857 Hz，但与 7.974 Hz 差距不足，算法判"无明确谱线"，不输出结论。
4. **与 620 rpm 比对**：视频一 11.134 Hz = 668 rpm，比标称高 7.7%；视频二候选 10.857 Hz = 651 rpm，高 5.0%（未通过判据，仅供参考）。偏差可能来自电机实际供电/负载下的转速、减速电机标称容差，或手机视频时间戳；没有转速计或已知频率激励无法区分。**不能把 10.33 Hz 写成本次测得结果**，也不能反过来据此说明算法有 7% 误差。
5. 振动在这两段视频里主要表现为亮度/反光变化（离面运动），而不是面内平移。要定量测位移，需要换实验条件，见文末"下一次拍摄建议"。

## 视频结果

ROI 均为 32×32，按首帧纹理图选取（板端角、板边中部、参考区），选定后没有按位移谱结果调整。图：[视频一测点](video1/roi.png)、[视频二测点](video2/roi.png)。

### 视频一（较稳，俯视板面）

参考区只能选电机外壳——画面里没有纹理足够的静止背景。电机外壳也在振动源上，所以"相对"结果是"相对电机外壳"，不是相机补偿。

| 测点 | LK | NCC 原始 Y | NCC 相对电机外壳 Y |
|---|---|---|---|
| tip_upper | 无效：29 帧未收敛 | 0.51 Hz，0.44 px | 0.61 Hz，0.16 px（不明确） |
| tip_lower | 无效：单边缘，初始化拒绝 | 0.51 Hz，0.49 px | 1.19 Hz，0.20 px |
| edge_lower_mid | 无效：28 帧失锁 | 无效：失锁 | — |
| edge_upper_mid | 无效：7 帧未收敛 | 0.51 Hz，0.46 px | 0.54 Hz，0.17 px |
| motor_body（参考） | 有效：X 0.87 Hz 0.65 px，Y 0.51 Hz 0.48 px | 同左 | — |

在 11.134 Hz 处的位移幅值（不是程序输出，是核对用的检查）：电机外壳 LK X 0.036 px / Y 0.027 px，tip_upper NCC 0.018/0.031 px，都与 5–12 Hz 噪声中位数（0.015–0.05 px）同量级。

全视场谱线：[field_spectrum.json](video1/field_spectrum.json)，有效；11.134 Hz（22.7% 的活动格），7.728 Hz（2 倍频混叠），3.421 Hz（3 倍频混叠）。

### 视频二（手持，旋转/透视变化大）

全部板件测点和墙面参考点都被拒绝（NCC 触边/失锁；LK 未收敛 219–220 帧、失锁）。单个参考点相减只能扣平移，扣不掉旋转/透视，这与分工文档 §5.4 的判断一致。全视场谱线判"无明确谱线"（10.857 Hz 占 2.0%，7.974 Hz 占 1.7%）。

完整数值：`video*/analysis_lk.json`、`analysis_ncc.json`；逐帧数据 `*_lk.csv`、`*_ncc.csv`；跟踪器初始化信息 `log_*.txt`。

## 下一次拍摄建议

- 三脚架固定相机；侧面拍板件自由端的边缘，使弯曲振动落在像面内（俯视板面时弯曲主要是离面运动，只改变亮度）。
- 在板端和独立静止背景各贴一个哑光、二维纹理的小标记（散斑贴纸或打印棋盘角），避免 ROI 只含一条边或混入阴影。
- 固定曝光、关闭手机自动曝光/防抖；尽量用短曝光。30 fps 时 1 倍频 10–11 Hz 在奈奎斯特内，但 2、3 倍频会混叠（本次已观察到），能用 60 fps 更好。
- 同时记录一个独立参考：转速计/光电测速，或已知位移的标定振动，用来区分"电机实际转速"与"时间戳误差"。

## 对分工文档的意见

总体合理：PL 只出带帧号/时间戳/质量的位移，PS 管补偿、标定、频谱和记录，ESP32 只管辅助外设且不碰测振结论，边界清楚，也与本次实现一致（ESP32 无需改动）。补充几点：

1. §5.2"先采用与当前 PS NCC/ZNCC 一致的计算"：建议改为"PL 采用共享乘加引擎，整数 ZNCC 搜索与 LK 亚像素更新复用同一累加核"。本次数据表明 NCC 抛物线插值有约 0.13 px 系统误差，单独为它做 PL 亚像素硬件不划算；`lk_accum` 已同时提供 ZNCC 所需的和。
2. §3 PL↔PS 输出字段建议补"是否收敛/迭代次数"和"所用整数初值"，便于 PS 区分失锁、触边与未收敛；本次视频里未收敛是 LK 测点无效的主要原因。
3. "视觉增强"一行可加"全视场谱线（主频分布）"：当前在 PS 每次测量后算一次；若要实时，可在 PL 用少数频点的滤波器组，与现有时间带通复用状态存储。它只给频率，不给位移单位，应和位移结果分列。
4. §5.4 背景补偿：本次视频一没有合格的静止背景，只能相对电机外壳；建议测点规划时把"背景参考标记"作为现场安装要求写入操作流程。
