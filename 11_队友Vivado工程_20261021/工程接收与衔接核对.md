## 硬件数据通路

工程入口：`AX7010_Engineering_Package_20261021/AX7010_Sdoira_PL_V1/project/stereo_depth.xpr`。

工具记录为 Vivado 2025.2，器件 `xc7z010clg400-1`；目录中的 `AX7010_2023.1` 是被引用的课程/IP 目录，不能据此判断当前 XPR 版本。

BD 的主要连接为：

1. 两路 OV5640 → 各自 AXI Stream/VDMA 写通道 → PS HP0 → DDR。
2. DDR 显示缓冲 → VDMA 读通道 → Video Out → RGB2DVI → HDMI。
3. `sdoira_bm_axi_0` → 独立 DDR AXI 桥 → PS HP1；控制寄存器位于 `0x43C20000`，范围 16 KiB。
4. FCLK0 为 100 MHz，用于控制与 BM；FCLK1 为 125 MHz，用于视频/HP0 数据运输。

BM 文档及 RTL 包含 SAD、亚像素视差、唯一性筛选与弹性 AXI 桥。文档描述的输入为 ARM 预处理后的 320×180 图像、7×7 匹配窗、64 视差范围，输出有效搜索区域 249×174。并非直接对全分辨率双目图像完成已标定的三维测振。

## 裸机 PS 跟踪与频谱

- CPU0：摄像头配置、VDMA/显示控制、界面绘制与网络传输。
- CPU1：从两路 DDR 图像各取一个目标 ROI 和一个背景 ROI，共四个跟踪器。
- 源码采用 96×96 采集 ROI、41×41 固定模板、平移型逆组合迭代跟踪；与我们 Linux 版本的 NCC 搜索实现不同，不能直接混用其质量阈值。
- 两个目标及两个背景的位置目前硬编码在 `tracking_worker.c`，不是触屏任意选点的完成版。
- 频谱为左右相对位移的 X/Y 四通道；256 点窗、每 64 个样本更新，去均值/线性趋势、Hann 窗、FFT、静止基线和候选谱峰判定。
- 包内 verification.json 记录约 45 Hz 采样、最大 FFT 批次耗时约 0.944 ms，并记录与 NumPy 的谱幅对比通过。这是保存的历史记录，本次没有板端复测。
- 输出为原生像素估计；没有完成毫米标定、双目三维标定和传感器曝光硬同步。

CPU1 自行建立 MMU、使用固定内存地址、独立入口和栈，通过共享内存与 CPU0 通信。`depth_worker.elf` 是历史名称，当前源码为跟踪/频谱 worker；不能凭文件名判断为深度推理程序。

## 保存的实现报告需要怎样解读

`elastic_optimized_timing.rpt` 为 Routed 报告：WNS +0.004 ns、WHS +0.018 ns，已约束的 setup/hold 无失败端点。但同一报告还列出：

- 592 个 no_clock 寄存器/锁存器时钟引脚，来自两路 CMOS PCLK。
- 1132 个未约束最大延迟的内部端点。
- 20 个输入无 input delay、6 个输出无 output delay。
- 1 个 generated clock 未连接时钟源。

因此不能将“所有用户指定约束满足”写成“所有路径时序闭合”。修改硬件前应补齐摄像头输入时钟、外部延迟及 CDC 约束，再检查完整时序。

保存的 DRC 报告列出 59 项 Warning，没有 Error 行；Warning 涉及时钟连接、BRAM 异步控制、DSP 流水线等，不等于零问题。包内文档记录修订版约 15542 LUT（88.31%）和 39.5 BRAM（65.83%），这里只作资源预算线索：需要从最终 DCP 重新导出完整 utilization。顶层 synth utilization 含 OOC/黑盒阶段的 0 LUT 数字，不能把它当成整机资源为零。

最终保存位流对应 `board_elastic_optimized.dcp`。普通 XPR 的 impl 运行状态不保证代表这个优化后 checkpoint。包中没有 XSA，不应拿旧硬件平台文件代替当前导出。

## 与载板及 Linux 路线的衔接

已完成静态对比：

- 队友三份顶层 XDC 的 37 项显式封装引脚与载板 34 项引脚没有重叠；不包括差分互补脚等工具隐式分配，也不替代合并后 Vivado 的 I/O/Bank 检查。
- 现有 BD 未包含 `carrier_ctrl`、载板三路 AXI IIC、两路 UART16550 和 Quad SPI，保存的 bit 不能直接控制全部载板功能。
- 现有 PS 控制地址在 `0x41200000`、`0x43000000` 等区段；载板规划 `0x44000000`～`0x44060000`，显式地址区间没有重叠。
- 现有中断 concat 为 2 路，载板脚本需要再追加 7 路；静态数量在 IRQ_F2P 16 位以内，实际连线及设备树编号仍需合并时确认。
- FCLK0 100 MHz 与载板控制设计吻合，但必须核对 BD automation 结果、复位与各外设时钟。

最终继续沿用用户确认的 Linux＋PL 路线。裸机程序不能直接作为 Linux 应用运行，也不能直接与普通 SMP Linux 同时占用 CPU1、固定 DDR、VDMA 和中断。若保留专用裸机 CPU1，需要单独设计 AMP、内存预留、缓存一致性和启动管理；当前没有这套集成。

Linux 迁移的关键不是将 `/dev/video0` 改一个名称，而是接入实际摄像头驱动/媒体通路或受管理的帧缓冲接口，明确 DMA 缓冲所有权、序号、时间戳和显示输出。Linux framebuffer UI 与当前裸机 HDMI 帧缓冲也需要统一显示方案。
