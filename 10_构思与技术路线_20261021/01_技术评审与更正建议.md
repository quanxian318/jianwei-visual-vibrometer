# 见微视觉测振仪：技术评审与更正建议

评审日期：2026/10/21。输入为用户提供的同名 Markdown、Word 和 9 页 PDF；Word 中的系统架构、六阶段路线两张图均已读取。原始文件保持不变。

结论：保留“低频、多测点、运动可视化”的定位和双支路思路；让 FPGA 直接输出位移与质量指标，并实现受限 ROI 的视频放大。需要修正测量边界、同步、频谱定义和部分硬件表述，补齐可综合的算法规格、存储预算与对照实验。

## 一、应更正的内容

| 原稿位置／表述 | 更正建议与理由 |
|---|---|
| 项目定位：加速度计只测一个点、激光测振不能看到振型 | 单只加速度计通常测一个安装位置，多通道阵列可同时测多点；扫描式激光测振也可重建振型。突出本项目同一视场多点、低成本与可视化的组合，不以绝对说法描述其他方法。 |
| 测量原理：“可测频率上限＝帧率的一半” | fs/2 是理想均匀采样的奈奎斯特边界，不是保证可测频带，工作频率须严格低于该边界。45fps 时20Hz只有2.25样点/周期，初版建议先验证0.5–10Hz，再把10–20Hz作为逐项校准的扩展范围。这个建议不是采样定理要求固定4～5点/周期，而是首板工程取舍。 |
| “实测可达45fps” | 尊重原稿已有观测，保留为“原稿记录约45fps”；补充分辨率、单／双路、格式、曝光、采集链路和原始时间戳日志。界面刷新率、相机规格和实际有效采样率要分开。 |
| 曝光未进入幅值误差预算 | 近似矩形曝光使正弦位移幅值乘以 sinc(πfTexp)。例如20Hz、20ms曝光约为0.757，幅值衰减约24%；这只是理想示例，实际还受卷帘快门、追踪与成像影响。短曝光与稳定补光应进入验收条件。 |
| “像素到毫米需要ToF或双目距离” | 已知尺度的平面标定也能给出mm/px，ToF并非必须。dmm≈dpx·Z/fpx仅适用于校正后的近似正视、固定深度、小面内运动；倾斜面需局部映射／单应性。ToF视场和光轴不等于每个图像ROI，需外参或同平面验证。 |
| “单目只看得到垂直于视线的振动” | 普通二维位移测量主要对像平面方向敏感。轴向运动也可能表现为尺度和透视变化，但单目二维模型不能据此宣称已可靠测出轴向位移。 |
| “所有数据都用同一计数器打时间戳” | PL统一记录帧边沿和DRDY等事件；曝光时刻、读出时刻和传感器内部采样时刻仍有偏移。两相机有同一时基不等于曝光同步，传感器也有各自ODR、滤波群延迟和FIFO。需记录并标定各项偏移。 |
| 单帧内多个ROI当作同时测量 | OV5640为卷帘快门器件。不同图像行对应不同曝光时刻，比较多点相位／振型、左右目动态匹配时需评估行时间差；未完成标定时只展示各点幅值趋势，不称已获得同步模态振型。 |
| 频谱：“频率分辨率＝1/采集时长” | 1/T首先是完整记录DFT的频率网格间距；实际可分辨能力受窗函数、信噪比及估计方法影响。Welch应按分段长度计算频率网格；零填充不会增加物理分辨能力。主频误差也不能自动保证≤1/T。 |
| “速度由2πf×位移推得” | 该关系对同一频率分量成立，且幅值定义须一致。多频信号的带限速度RMS应逐频率加权／积分，不能用主频乘整段位移RMS。位移、加速度之间也应同频、同轴、同带宽比较。 |
| 报警：“双目一致才报警”且能避免光照误报 | 左右目可能受到共同光照闪烁影响，也可能因投影方向不同而幅值不同。先检查几何映射、质量和时差，再做一致性判据。无效结果显示“测量无效／需重测”，不判正常，也不自动清除已有报警。 |
| 以ISO10816和10–1000Hz概括分级 | 写成“自定义低频带限阈值”，说明设备、工况、频带、方向及RMS／峰值定义。ISO10816-1已由ISO20816-1替代；系列各部分适用对象和频带并非完全相同。本项目不把低频带限结果等同标准机器宽带评级。 |
| 风险表：ADXL345与IMU只需切换SPI模式 | 还须检查GY-291的SDO是否硬接地，以及ADXL345在CS高时可能误识别其他SPI流量为I2C的问题；当前载板没有厂家建议的SDI隔离或门，仅切Mode不能证明共享总线可靠。 |
| “PL做全部外设接口” | 限定为载板经J11接入的实时接口及视频链路；网口、USB触摸、启动SD等由PS侧接口／Linux驱动管理。打印串口经PL，打印作业策略属于PS。 |
| RTC、INA226负责掉电报警 | DS3231提供日历时间，INA226监测电流／电压／功率；快速掉电预警是U102比较器链路。板上没有支持完整Linux关机的储能保证。K101请求关机后仍需用户断开总开关。 |
| 备用录像走同一链路 | 若声称验证PL，需将原始帧及采样时间输入同一个PL内核。电脑播放预先放大的视频只算展示，不能作为FPGA在线算法的证明；回放模式需清楚标识。 |

## 二、FPGA应补充的具体交付

### 1. 位移测量核

推荐以平移模型的梯度迭代／逆组合LK为候选基线，在软件中先验证；若队友已有更合适且能通过对照的内核，先比较再冻结。模板匹配SAD可用于整数初定位，相位相关作为软件对照。不要同时把三套方法全部列为首版必须实现。

PL负责ROI双缓冲、梯度／残差积累、亚像素插值、有限次迭代、置信度和异常标志。PS负责选择ROI与模板、提供配置／标定、读取结果。验收要求包括定点模型与RTL逐帧一致，以及浮点与定点的误差统计。

### 2. 运动放大核

采纳空间低通和降采样、少层金字塔分解、逐像素时间带通、增益限制、上采样重建与ROI融合。首版限制显示区域与层数；计量支路始终读取未放大图像。上采样不会恢复已丢失的细节或提高测量精度。

这一路很适合体现流式处理，但资源重点往往是跨帧滤波状态，不只是乘加次数。320×240图像、每像素两个16bit状态需要307200B，即300KiB，已超过Zynq-7010总计60个36Kbit BRAM块的原始比特容量约270KiB，且尚未计其他模块。按32bit数据宽度使用BRAM时可用容量还会受校验位和组织方式影响。应限制区域、层数或将状态明确放入DDR。

### 3. 可见、可测的优势

同时提供：每帧核心计算周期、端到端延迟及其分位数、丢帧／FIFO溢出、CPU占用、DMA流量、后布局布线资源与时序，以及同输入软件／硬件的误差。若两种方案都能跑45fps，不能以相同显示帧率编造倍数加速；比较核吞吐余量、延迟、CPU释放和功耗／有效结果能量。

## 三、建议的开发优先级

1. 实际相机模式、曝光与时间戳证据；离线位移和放大算法基线。
2. PL实现至少4个测量ROI，另留背景参考ROI；共享一个运算引擎轮询，先满足每帧预算，再增加并行度。
3. 定点与RTL验证、DMA结果和质量状态；输出位移波形与有效性。
4. 实现受限ROI的少层欧拉运动放大和上采样重建；显示与测量分别验收。
5. 完成尺度、时间、曝光响应及参考通道对照，再加入双目稀疏尺度／一致性；FFT加速和全幅相位法留待资源报告后决定。
6. 集成打印、语音、NFC和MQTT，进行完整现场演示与同输入软件／FPGA对照。

详细建议见配套《构思与技术路线_FPGA核心方案建议稿》。没有重写旧团队交接包中的已约定接口；采用本架构后需同步实际Vivado工程、设备树、软件和交接文档。
