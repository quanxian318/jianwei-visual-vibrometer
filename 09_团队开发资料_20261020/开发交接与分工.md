# 开发交接与分工

本文件把当前接线事实与双方要实现的软件接口放在同一个交接点。硬件团队按真实电气编号接线；Nano和AX开发者共同采用[协议V1](06_通信协议与配置/PS_Nano协议V1.md)。

## 系统数据流

```text
AN5642 → AX7010 J10 → PL视频输入/VDMA → DDR → Linux视觉测量 → HDMI界面/结果存储/打印
前面板旋钮、按键 → 主板J502 → AX J11 → PL同步消抖/事件 → Linux
Linux统一状态 → PL WS2812控制器 → U502电平转换 → 前面板HL101…HL105
LSM6DSV、ADXL345 → J702/J703 → PL共享SPI + DRDY时间戳 → Linux
VL53L1X、SHT40 → J701/J704 → PL I2C1 → Linux
Linux ↔ PL UART ↔ Nano ESP32 ↔ PN532、辅助SD、I2S功放、Wi-Fi/NTP
Linux → I2C0 TCA9555 → 打印机供电/通信、报警、风扇、ToF关断、Nano复位
Linux → PL第二路UART → 主板J401 → EM5820H
```

## 各自负责什么

| 模块 | AX7010 PS/Linux | AX7010 PL | Nano ESP32 |
|---|---|---|---|
| 相机/显示 | 模式配置、视觉算法、界面、结果存储 | 视频采集、VDMA及时间戳 | 无 |
| 前面板 | 操作状态机、五灯颜色语义 | 触点同步/消抖/正交解码、WS2812时序 | 无 |
| 两路补光 | 亮度和采集/打印互斥策略 | 两路PWM输出 | 无 |
| 板内管理 | TCA9555、INA226、DS3231驱动 | I2C0电气/AXI接口 | 掉电输入监测 |
| 外接传感器 | 型号识别、驱动、数据质量/标定 | I2C1/2、SPI、DRDY捕获 | 无 |
| 打印 | 纸张状态、任务队列、供电状态机、编码 | UART和CTS | 无 |
| NFC | 测点绑定及业务判定 | 转发串口 | SPI读卡、UID事件去重 |
| 语音 | 决定播放/取消，处理完成事件 | 转发串口 | SD读取、I2S输出、音量/欠载管理 |
| 网络时间 | 决定采纳NTP、更新RTC/系统时间 | 转发串口 | Wi-Fi/NTP获取与状态上报 |

主应用保存最终测量记录，是报警/界面/打印的共同事实源。Nano不直接控制打印机，也不直接读取主板I2C传感器；不能通过修改Nano程序访问没有接到Nano的引脚。

## 首次开发即可使用的资料

硬件工程、260条板载BOM、两板原理图和PCB网表、全部连接器针序、30针Nano/GPIO表、34个FPGA约束、上电顺序、器件手册和协议参考编解码器已包含在包中。队友可立即完成引脚配置、软件模块边界、消息编解码、模拟外设和基础驱动开发。

## 必须由实际工程填写的内容

| 项目 | 负责方 | 取得/完成方式 | 影响 |
|---|---|---|---|
| AX7010板卡修订、Vivado/PetaLinux匹配版本 | AX开发者 | 厂家随板资料及可跑AN5642/HDMI的基础工程 | 先跑通视频/显示，再合入J11载板 |
| XSA、bitstream、设备树、AXI基地址、IRQ、Linux节点 | AX开发者 | 实际Vivado导出及Linux启动枚举 | 填AXI与Linux设备映射模板；不能套用空地址 |
| Nano板包、core版本、库清单 | Nano开发者 | 在可编译ABX00083环境锁版本 | I2S/硬件流控API随core变化，需按对应版本实现 |
| EM5820H串口命令、针序、波特率、CTS和完成查询 | 硬件＋AX | 用户已确认12V版；取得实物批次说明/自检页 | 只确认型号和电压仍不能猜TX/RX标签方向 |
| GY-291实际模块的SDO、CS及供电结构 | 硬件＋AX | 通断/电压检查及单模块、共享总线测试 | SDO被0Ω接地时不能直接接共享MISO |
| 传感器轴向、尺度、带宽、报警限值 | 应用开发＋测量负责人 | 已知激励/位移标定 | 未标定时显示工程调试值，不发布保证精度 |

Wi-Fi凭据由设备配置输入，不在资料包写入个人账号。相机基础工程不与本载板的I2C0/1名字混淆：相机SCCB走J10，板内三路I2C走J11，设备树应使用明确别名。

## 两端约定的最小联调目标

先在115200、8N1下实现HELLO、GET_STATUS和事件收取，随后测RTS/CTS并切到921600。Nano复位后生成新的boot_id，AX丢弃上一启动会话中尚未完成的任务状态。软件不自动重放打印和音频等有实际效果的任务。

AX开发者先交付可读写板内I2C、可收发Nano UART、可驱动前面板五灯及读取旋钮的最小系统；Nano开发者交付USB日志、UID事件、SD文件播放和掉电事件。再合并视频测量与打印，避免所有模块同时启用后无法定位问题。

## 最终给硬件使用者的交付物

AX软件提供匹配的启动文件、bitstream、设备树、应用、构建步骤、板卡/工具版本和设备映射。Nano提供源码、板包/库版本、二进制、烧录方法和语音文件清单。双方共同提供协议测试结果、配置样例、已知限制及验收记录；不能只交一个无法重建的烧录文件。
