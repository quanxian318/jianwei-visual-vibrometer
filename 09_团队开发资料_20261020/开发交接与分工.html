开发交接与分工

本文件把当前接线事实与双方要实现的软件接口放在同一个交接点。硬件团队按真实电气编号接线；Nano和AX开发者共同采用协议V1。

Linux统一状态 → PL WS2812控制器 → U502电平转换 → 前面板HL101…HL105
LSM6DSV、ADXL345 → J702/J703 → PL共享SPI + DRDY时间戳 → Linux
VL53L1X、SHT40 → J701/J704 → PL I2C1 → Linux
Linux ↔ PL UART ↔ Nano ESP32 ↔ PN532、辅助SD、I2S功放、Wi-Fi/NTP
Linux → I2C0 TCA9555 → 打印机供电/通信、报警、风扇、ToF关断、Nano复位
Linux → PL第二路UART → 主板J401 → EM5820H

两端约定的最小联调目标

先在115200、8N1下实现HELLO、GET_STATUS和事件收取，随后测RTS/CTS并切到921600。Nano复位后生成新的boot_id，AX丢弃上一启动会话中尚未完成的任务状态。软件不自动重放打印和音频等有实际效果的任务。

AX开发者先交付可读写板内I2C、可收发Nano UART、可驱动前面板五灯及读取旋钮的最小系统；Nano开发者交付USB日志、UID事件、SD文件播放和掉电事件。再合并视频测量与打印，避免所有模块同时启用后无法定位问题。

最终给硬件使用者的交付物

AX软件提供匹配的启动文件、bitstream、设备树、应用、构建步骤、板卡/工具版本和设备映射。Nano提供源码、板包/库版本、二进制、烧录方法和语音文件清单。双方共同提供协议测试结果、配置样例、已知限制及验收记录；不能只交一个无法重建的烧录文件。
