# MP34DT01 音频辅助测振与 J706 复用方案

日期：2026/10/22。MP34DT01 模块用 3V3、GND、CLK、DAT 四线接主载板 J706，由 AX7010 处理音频，辅助视觉测振。本文是当前设计：PL 接收核、PS 抽取与分析、记录、界面和两套 Vivado 集成脚本已实现并通过主机测试，尚未上板；PCB 与网表不改。

## 1. 方案定位

以视觉多测点位移为测量主链，新增一个空气声学参考通道，辅助识别周期性、比较主频和谐波、记录声音随工况的变化。PL 产生 PDM 时钟，在有效半周期采样，缓存原始码流并计时；PS Linux 做抽取滤波（与参考模型逐位一致）、谱分析、质量判断、显示和记录。麦克风不接 Nano，不占用 Nano 到 MAX98357A 的 I2S 语音输出。

MP34DT01 输出 **PDM 单比特码流**，需要外部 CLK，不能按 I2C 传感器读取，也不能直接当作已经解码的 I2S/PCM 音频。ST 手册给出正常供电 1.64–3.6V、时钟 1–3.25MHz；3.3V 和采用的 2MHz 在该范围内。规格依据为原厂 MP34DT01、DocID022331 Rev12，第 5–8、14 页，见[本地手册](../02_数据手册/MP34DT01_ST_DocID022331_Rev12.pdf)与[ST 原稿的 DigiKey 副本](https://media.digikey.com/pdf/data%20sheets/st%20microelectronics%20pdfs/mp34dt01.pdf)。这些是芯片要求，模块是否含稳压器、L/R 如何固定仍按实际模块核对。

音频幅度使用数字满量程单位（dBFS）；未经声学校准不输出 dBSPL，更不能将其换算为 mm、mm/s 或 g。声音峰可能来自电机、气流、风扇或其他结构，不能自动归属到某个图像测点。

## 2. 当前实现与验证边界

PL接收核已与双目一起生成并在裸板加载，PS抽取、分析、记录和界面已实现。实际麦克风、SEL及线束波形、持续声学采集尚未完成验收，不能将手机视频录音的离线结果当作MP34DT01实采。

单麦模块SEL直接接芯片L/R时，方案选择SEL→模块GND；先确认模块没有内部固定到3V3。J706仍为3V3/GND/CLK/DAT四线。详见[模块设置](../04_使用指南/模块上电前设置_SEL与NFC拨码.md)。

当前板端及代码事实分别见[冻结实测](../05_验证资料/板端冻结/冻结说明与当前事实.md)、[软件入口](../06_软件与FPGA/README.md)和[三侧对接审查](../05_验证资料/三侧对接/三侧对接审查.md)。

## 3. J706 实际针序与复用

依据[最新主载板 PCB 工程提取网表](../01_硬件工程/网表/工程提取_主载板PCB_20261020.enet)与[XDC](../06_软件与FPGA/ax7010/pl/constraints/AX7010_carrier_V1.10.xdc)，连接如下。已制板网络名保留；XDC 中两脚的端口名改为 `mic_clk`/`mic_dat`，管脚不变。

| J706 电气针号 | 已制板网络名 | 麦克风模块端 | 实际通路及方向 |
|---|---|---|---|
| 1 | 3V3_SENS | 3V3/VDD | 主载板受时序控制的传感器 3.3V 电源 |
| 2 | GND | GND | 公共地 |
| 3 | I2C2_SCL | CLK | J801-32 → AX7010 J11-32 → H16，PL 推挽时钟输出 `mic_clk` |
| 4 | I2C2_SDA | DAT/DOUT | J801-33 → AX7010 J11-33 → G15，PL 数据输入 `mic_dat` |

J706 另外的 5/6 是接地机械固定焊盘，不是线束上的第 5/6 根功能线。模块四针的物理排列不保证与 J706 相同，按名称制作转接线；1 脚以实际焊盘编号/现有引脚图核对，不凭插头朝向判断。板端为 GH1.25 四针，配套线端按现有 J706 板端型号购买。

两根信号的网表端点仅为 J706、J801 和各自上拉电阻：R710 将 CLK 网经 4.7kΩ 上拉至 3V3_SENS，R711 对 DAT 网同样上拉。没有串在路径上的电平转换器或 RC 低通。因此可以复用现有铜线，不需要为此改板；MHz 级信号的实际波形须在线束上实测。

接线与使用要求：

- 原 I2C2/热成像预留用途已由本方案替换，PDM 工作时不再接 MLX90640 或其他 I2C 从机。I2C1 上的 ToF/SHT40 保持原连接。
- 原 4.7kΩ 上拉不是 PDM 必需器件。首板先保留，3.3V 低电平负载约 0.70mA；按实际波形决定是否拆除。CLK 由 PL 推挽输出（8mA、慢边沿），不用开漏加上拉产生。未增加并联电容。
- 确认模块接受 3.3V，DAT 为兼容 LVCMOS33 的输出，L/R 已固定为高或低，不允许悬空。[ST AN4227，表 1–2](https://www.st.com/resource/en/application_note/an4227-audio-hub-demonstration-kit-supporting-the-m45dt02-mp34db01-and-mp34dt01-microphones-stmicroelectronics.pdf)。程序启动时自动判断数据在哪个半周期（§4），也可在配置中固定。
- CLK 在禁用、复位和掉电时为低：接收核在 EN=0、复位或 kill 时把时钟拉低；载板设计把滤波后的 PFAIL 接到 kill，掉电时硬件立即停钟，PS 收到掉电也停止采集。启动后丢弃前 50ms（芯片启动与滤波器建立）。
- 原型线束以短线开始（建议 J706 到模块不超过 10cm，另计 J801—J11 排线），CLK/DAT 尽量贴近地回路，远离 Buck、电机与风扇供电；长度不是已验证上限。模块自带去耦优先复用，不足时在模块电源脚旁补充去耦。
- 麦克风固定在独立支架或机壳合适位置，声孔朝向被测设备、避开风口；记录距离、朝向和风扇状态，不直接粘在铝片上充当接触式加速度计。

## 4. 实现

```text
MP34DT01 DAT ─▶ PL pdm_mic：2MHz CLK、有效半周期采样、32 位字、8192 字 FIFO、字序号与时钟戳
                    │ AXI-Lite 读取（每 10ms；FIFO 可存 131ms）
                    ▼
PS vibmond：CIC 5 阶 /32 ＋ 63 阶 FIR /2 → 16 位 31,250 S/s（与参考模型逐位一致）
            ├─ 环形缓冲（60s，更长的测量开始时扩容）、断段记录、样本序号 ↔ CLOCK_MONOTONIC
            ├─ 与视频同一时间窗：电平、包络谱、直接谱、与视觉频率对照
            └─ 界面、记录（acoustic 段、acoustic.wav、acoustic_spectrum.csv）
Nano ESP32 ─▶ 原有 NFC / 辅助 SD / I2S 语音 / 联网
```

### PL：接收核 pdm_mic

源码 `06_软件与FPGA/ax7010/pl/audio/rtl/pdm_mic.v`，寄存器表在其头注释，与 PS 的 `drv/pdm_regs.h` 由单元测试逐项核对。

1. 时钟：系统时钟 100MHz，每半周期 HALF_DIV=25 个时钟，得 2.000MHz、50% 占空比，由寄存器直接驱动引脚，不经门控或全局时钟网络。
2. 采样：DAT 经两级同步，在所选半周期开始后第 SAMPLE_AT=18 个时钟取 1 位（引脚处约在半周期开始后 160ns、结束前 90ns）。PHASE=0 对应 L/R=GND（CLK 低电平时数据有效），PHASE=1 对应 L/R=VDD。另一半周期 DAT 为高阻，读到 R711 上拉的 1，所以相位不对或没有模块时读到全 1。
3. 缓存：32 位一字（bit0 最早），FIFO 8192 字（131ms）。FIFO 满后冻结：之后的字全部丢弃并计数，直到 PS 清除 OVERFLOW，因此 FIFO 里不会同时有缺口两侧的数据。读 WORDS 寄存器时同时锁存 FIFO 深度、丢字数、正在填充的位数和时钟计数，PS 由此得到队首字的序号（WORDS−DROPPED−LEVEL）和最新一位的采样时刻。
4. AXI-Lite 地址 0x44030000（4KiB），无中断，PS 轮询。kill 输入：载板设计接 PFAIL，队友工程接 0。
5. 抽取放在 PS 的原因：队友 AN5642 双目设计已基本用满 slice，把 CIC＋FIR 放进 PL 的版本布局失败（器件 4400 个 slice，布局时剩余可用 2718 个，未放置的逻辑需要 2911 个）；因此 PL 只保留接收与计时。PS 的代价是每秒 62,500 次 AXI-Lite 读和抽取运算（x86 上 1.8ms/秒音频，A9 耗时待上板实测）。

### PS：采集服务、分析、记录与显示

- 驱动 `drv/pdm_mic`、服务 `app/acoustic_service`。状态：disabled → starting → warmup → ready ⇄ capturing。位流里没有接收核，或接收核在但两种半周期都读不到麦克风数据时为 absent（未接入，不算故障）：前者不再重试，后者每 5 秒重试，插上模块即可恢复。其他异常为 fault，5 秒后重试。启动时用 100ms 测量 PL 时钟相对 CLOCK_MONOTONIC 的频率，采样率和时间都按实测值计算。
- L/R 自动判别（`phase=auto`）：先在一种半周期采样 10ms，1 的比例不在 2%–98% 之间就换另一种；两种都不行即为未接入（“无麦克风数据（未接或 DAT 异常）”）。`phase=low/high` 固定一种，不对时为故障“所设相位无数据”。
- 抽取 `measure/pdm_model`：CIC 5 阶 /32（字节查表）、63 阶 Q17 FIR /2，系数由 `tools/pdm_fir_design.py` 生成。0–10kHz 波动 ±0.003dB，FIR 阻带（15.625kHz 起）−85dB，混入 0–10kHz 的最差混叠 −72dB；群时延 534.75µs，样本时刻已扣除。PDM 满量程对应 ±32768，满量程正弦为 0dBFS。
- 时间：每次读取用锁存的时钟计数把最新一位换算到 CLOCK_MONOTONIC，再对应到 PCM 样本。测量结束后按视频首帧时刻和时长从环形缓冲截取同一窗口；数据不足、跨断段或到得太晚分别记为 not_buffered、gap、late，不拼接。
- 分析 `measure/acoustic`（同一窗口；视觉频率只参与最后的比较，不影响声学估计）：电平 dBFS、削顶比例、无变化/无信号检查；100Hz–10kHz 最强音调；四个候选声频带（200–1000、1000–3000、3000–8000、1000–8000Hz）分别求包络谱（带通、整流、低通、降到约 1250Hz、Hann 窗、4 倍补零），取峰最突出的频带，在 10–100Hz 找包络峰；同时找 10–100Hz 直接谱峰。峰值门限随频点数自适应，不低于 8dB。与视觉对照：一致 agree、整数倍或几分之一 harmonic、不同 differ、无视觉 no_visual、无包络峰 no_peak；容差 max(0.2Hz, 2/T, 2%×视觉频率)。
- 测量窗口内不启动新的语音提示，正在播放的语音停止；风扇、蜂鸣器状态写入记录。声学结果失效不影响视觉结果；视觉无效时声学结论照常记录，但不当作有效测振。
- 记录 `record.json` 的 `acoustic` 段：available/valid/reason、来源、L/R、PDM 时钟、实测采样率、滤波链与时延、窗口（首样本序号、样本数、相对首帧的偏移）、电平、各候选频带结果、包络峰与直接峰、最强音调、视觉对照（关系、两个频率、差值、容差、倍数）、工况、文件名。另存 `acoustic.wav`（单声道 16 位，WAV 头采样率为实测值取整，准确值以 sample_rate_hz 为准）和 `acoustic_spectrum.csv`（包络谱）。状态 JSON 有 `measurement.acoustic`（服务状态）和 `measurement.last.acoustic`（最近结论）。
- 界面：实时页预览左上角显示麦克风电平（启动中、故障另有文字，故障点按显示原因；未接入时不显示）；结果页详情行给出声学包络频率及与视觉的关系，频谱卡可切换“位移谱/声学包络”；设备页“声学麦克风”卡显示状态（就绪/采集中/启动中/未接入/故障）、电平、采样率、L/R 或原因。测量开始时未接入，则该次记录没有 acoustic 段。
- 配置 `acoustic`：enabled、source（pl/synthetic）、base、phase（auto/low/high）、warmup_ms、ring_s、poll_ms、save_wav、analysis_band_hz、carrier_bands_hz、min_prominence_db；`config/vibmon.json` 与 `config/an5642_board.json` 已启用。`source=synthetic` 生成调制音，用于无硬件测试。
- 离线工具：`tools/wav_acoustic <file.wav> [--visual Hz]` 用同一分析处理任意 16 位 WAV。

### ESP32：原职责保持

继续管理 PN532、辅助 SD、MAX98357A 语音播放、Wi-Fi/NTP 与掉电处理。音频不经过 Nano 辅助 SD 或协议 V1 传输。

## 5. Vivado 集成与约束

- 队友 AN5642 双目工程：`pl/bd/team_design.tcl` 依次执行 `team_bm_to_stereo.tcl`（去掉 BM，加入双目核与 DMA）、`team_add_pdm.tcl`（加入 pdm_mic，接 FCLK0 互连新增的一个主口，kill 接 0）和 `team_build.tcl`（综合、实现、位流与报告）；约束 `pl/constraints/pdm_mic_team.xdc`。Vivado 不能用中文路径，需把相关文件复制到 ASCII 目录运行。原双目设计已用满 slice（4400/4400），直接加接收核布局差 40 个 slice；因此双目 DMA 的存储侧改为 64 位、`bm_mem_intercon` 与 S_AXI_HP1 改用双目核的 40MHz 时钟，互连不再需要时钟和位宽转换（1340→485 LUT，DMA 实际只需约 1.2MB/s），双目核与视频显示通路不变。Vivado 2025.2 实现结果：接收核 251 LUT、352 FF、8 BRAM36；全设计 13495 LUT（76.7%）、18730 FF、slice 4337/4400（98.6%）、41.5 BRAM36、3 DSP；WNS +0.462ns（125MHz 视频域）、WHS +0.007ns，建立与保持均无失败端点，40MHz 双目域余量 1.155ns。位流 `06_软件与FPGA/ax7010/pl/stereo/bitstream/an5642_stereo_sgm40_pdm.bit.bin`（SHA256 `7d0b6f21de5d4bfa8ba6287fc52c6428d8a1e0b904e946aa3c653ae8d64e1188`），报告同目录，取代原纯双目位流；裸板已加载，实际麦克风与线束尚未验收。
- 载板设计：`pl/bd/add_carrier.tcl` 用 pdm_mic_0 取代原 iic_exp（同为 0x44030000）；`carrier_ctrl.v` 去掉 I2C2 的 IOBUF，输出 `pfail_kill`（滤波后 PFAIL 为低且 PFAIL 保护开启）接 kill；两份 `AX7010_carrier_V1.10.xdc` 把 i2c2_scl/sda 改名为 mic_clk/mic_dat，34 个管脚不变，mic_clk 为慢边沿 8mA；`system-user.dtsi` 去掉 &iic_exp，内核片段加 `CONFIG_DEVMEM`（vibmond 经 /dev/mem 访问接收核，无需设备树节点）。载板设计尚未在 Vivado 中运行。
- 时序：mic_clk 输出与 mic_dat 输入设 false path。时钟由寄存器产生、数据由系统时钟过采样，采样点由 SAMPLE_AT 决定，没有可做静态分析的源同步路径；实际余量上板后用示波器和 SAMPLE_AT 扫描确认。

- [ST AN4227](https://www.st.com/resource/en/application_note/an4227-audio-hub-demonstration-kit-supporting-the-m45dt02-mp34db01-and-mp34dt01-microphones-stmicroelectronics.pdf)，第 3 页供电、PDM 和 L/R；[ST UM1900](https://www.st.com/resource/en/user_manual/um1900-getting-started-with-the-digital-mems-microphone-expansion-board-based-on-mp34dt01m-for-stm32-nucleo-stmicroelectronics.pdf)，§2.2 PDM 经滤波抽取转换 PCM 的采集方法。
