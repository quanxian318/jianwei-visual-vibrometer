# PL、PS 与 ESP32 职责和接口分工

日期：2026/10/22。适用对象：AX7010 的 PL、PS Linux，以及 Arduino Nano ESP32 ABX00083。本文规定当前开发的目标分工；现有代码完成情况单独列出，不能把目标视为已实现。职责以本文为准，实际针序和电气连接以两板最新网表及引脚表为准。本次仅明确分工，不修改程序、RTL、PCB 或现有协议字节格式。

## 1. 总体边界

**PL 产生实时图像位移和硬件事件，PS 统一管理测量、分析和用户操作，ESP32 承担接到 Nano 的辅助外设。**

测量主链：相机 → PL 视频接收与 ROI 跟踪 → 带帧号、时间戳和质量信息的位移 → PS 运动补偿、标定与频谱 → 屏幕、记录和打印。

声学辅助链（接收位流已在裸板加载，麦克风实采未验收）：MP34DT01 → J706 → PL PDM 时钟/相位采样/原始码流缓存与计时 → PS 抽取滤波、包络谱与视觉频率核对；见[完整方案](MP34DT01音频辅助测振与J706复用方案.md)。

辅助链：PS ↔ PL 中的 UART 控制器 ↔ ESP32 ↔ PN532、主载板辅助 SD 卡、I2S 功放、Wi-Fi/NTP。

PL 和 PS 同在 Zynq 芯片内；PL 中的 AXI I2C/SPI/UART 控制器承担接口时序，驱动和业务决策由 PS 执行。ESP32 是独立协处理器，不负责主测振算法。

|---|---|---|---|
| 摄像头与视频 | 接收双摄视频、帧边界/序号、采集事件时间戳、缓冲及丢帧状态 | 相机模式、帧率、曝光配置；管理 DMA 缓冲、视频驱动和显示通路 | 无 |
| 测量 ROI | 按配置提取目标/背景 ROI，计算纹理和跟踪质量 | 用户选点、模板初始化/重建、ROI 和搜索参数、测点编号 | 无 |
| **振动位移提取** | **承担逐帧模板匹配、整数位移和最终亚像素位移计算，输出低质量、触边和失锁标志** | 初期保留亚像素拟合及软件参考实现，用于核对；决定何时停止测量或重新选点 | 无 |
| 相机/背景运动补偿 | 输出目标及背景各自的位移和质量 | 估计共同运动，输出目标相对位移；选择合适的背景模型 | 无 |

| 双目空间信息 | 资源允许且测量需要时运行双目匹配，输出视差及有效性 | 双目标定、图像校正配置、视差到深度/坐标换算及后续三维解算 | 无 |
| 视觉增强 | 资源允许时做降采样、时间带通、运动放大、能量图 | 频带/增益设置、伪彩映射和界面合成 | 无 |
| 前面板编码器/按键 | 输入同步、消抖、正交解码、事件捕获 | 短按/长按/旋转对应的界面和测量动作；触屏处理 | 无 |
| 前面板状态灯 | WS2812 时序、配置后的故障灯处理 | 决定各灯颜色和报警语义 | 无 |
| LED1 / LED2 | PWM/开关时序；按配置的 PFAIL/看门狗保护强制关断 | LED1 照明亮度；LED2 十字投影开关及测量互锁 | 无 |
| 风扇、蜂鸣器和打印供电 | 提供 TCA9555 所用的 I2C 接口 | 通过 TCA9555 控制负载，执行报警/打印电源状态机 | 无 |

| 电源/时钟管理 | PFAIL 事件和指定输出的硬件保护；I2C 接口 | INA226、DS3231、TCA9555 驱动、功耗策略、关机与记录收尾 | 本地 PFAIL 监测，关功放并停止辅助作业，报告电源事件 |
| EM5820H 打印机 | 第二路 UART 和 CTS 采样/接口 | 唯一打印任务管理者：供电、排队、编码发送、取消和完成判定 | 无 |
| PN532 NFC | 提供 PS—ESP 串口通道 | 将 UID 绑定到测点/工件，决定业务动作 | SPI 读卡、移卡检测和 UID 事件去重，上报 PS |
| 主载板辅助 SD 卡 | 无直接文件系统管理 | 查询状态、决定使用的语音资源；主测量记录写入 PS 自己的存储 | 唯一文件系统管理者：插拔、挂载、容量、资源文件读取 |
| 语音 | 无音频解码职责 | 决定提示内容、job_id、音量和取消；处理完成/失败事件 | 读 SD 音频、解析 WAV、I2S 输出、功放使能、欠载和作业管理 |
| Wi-Fi / NTP | 无无线协议职责 | 提交联网配置，决定是否采纳时间并更新系统/RTC | Wi-Fi 连接重试、凭据持久化、NTP 获取和状态上报 |
| 记录/屏幕/通信 | 输出所需的数据与硬件事件 | 测量记录、波形/频谱、六页 UI、触屏、历史、打印内容和 PS 网络应用 | 仅自己的 USB 调试和 PS 辅助协议，不承担 HDMI UI |

PS 是整机测量状态和最终记录的唯一管理者。界面、报警、打印读取同一份测量结果；ESP32 不自行给出“测量合格/超限”结论，PL 不决定界面流程。

## 3. 通信与数据所有权

### PL ↔ PS

- PS 经 AXI-Lite 配置硬件、读取状态；大图像使用受管理的 DDR/DMA 通路，位移结果按批次或事件通知 PS。缓冲区所有权、缓存一致性、帧边界和中断须在 Linux 集成时明确。
- 位移核的目标输出至少包含：帧序号、ROI 编号、硬件时间戳、X/Y 原生像素位移、相关/纹理质量、失锁/触边/饱和及丢帧状态。多测点须能按帧对应。
- 上述为待实现的语义要求，尚未冻结寄存器地址、定点格式、DMA 描述符或二进制 ABI；不能凭本文假定已有可调用硬件接口。
- 声学接收核 pdm_mic 在 0x44030000，PS 每 10ms 经 AXI-Lite 读取原始码流；读 WORDS 同时锁存 FIFO 深度、丢字数、半字位数与时钟戳，PS 由此得到样本序号和 CLOCK_MONOTONIC 时刻（已扣除 534.75µs 滤波群时延）。寄存器表见 `pl/audio/rtl/pdm_mic.v` 头注释。J706 原 I2C2 逻辑已从载板设计移除。
- PL 只记录它实际观察到的视频/事件时刻。帧到达时间不等于曝光时间；双摄曝光硬同步必须单独确认。NTP/RTC 负责记录的日历时间，不作为振动采样间隔基准。

### PS ↔ ESP32

- 复用[协议 V1](../04_使用指南/PS_Nano基础协议.md)和现有 `shared/vibproto`，通过 UART＋RTS/CTS＋事件 IRQ 通信；不传原始视频或高吞吐测振图像。
- PS 发起 HELLO、GET_STATUS、SET_NET、GET_TIME、PLAY_VOICE、STOP_VOICE、GET_SD_INFO、DRAIN_EVENTS、ACK_EVENTS、PREPARE_POWER_OFF；ESP32 返回响应并产生 NFC、音频、SD、网络、校时及掉电事件。
- 以 boot_id/session_id、请求 seq、音频 job_id 和事件 ID 区分重启、重试及重复事件。命令被接受不表示异步任务已经完成；语音依据完成/失败事件判断。
- 事件 IRQ 表示有未确认事件，不代表一次脉冲就是一张卡。重连后查询状态，不自动重放旧音频或打印作业。打印不经过 Nano 协议。
- 首次联调用 115200、8N1；当前 100 MHz UART16550 高速档两端统一用 781250。旧资料中的 921600 不作为当前硬件默认值。
- Wi-Fi 凭据保存在 ESP32 的 NVS；PS 统一管理测量配置和标定。ESP32 联网不会自动让 Linux 获得无线网卡、SSH 通道或视频传输能力。

### 存储与接线边界

主载板 J603 辅助 microSD 接 Nano，当前用于语音资源及状态查询；PS 主结果存储与 AX7010 启动/系统存储按实际部署配置。当前协议没有任意文件上传下载能力，不能将 J603 当作 Linux 直接挂载的共享盘。

Nano 的实际引脚分工以[board_pins.h](../06_软件与FPGA/nano_esp32/vibmon_nano/board_pins.h)为准：D2–D6 为 AX 通信与 IRQ，D7–D9 为 I2S，D10–D13 为 SD/SPI，A3 为 PN532 片选、A0 为 PN532 IRQ、A1 为 SD 检测、A6 为 PFAIL、A7 为功放使能。主板 IMU、参考加速度计、ToF、温湿度、RTC、INA226、打印机和前面板没有因此改接到 ESP32。

## 4. 状态机和保护的责任

| 层次 | 管理范围 | 发生异常时的职责 |
|---|---|---|
| PS 整机状态机 | 预览、准备、采集、分析、结果、打印、取消及关机等业务阶段 | 根据质量/丢帧决定结果是否有效；停止新任务、取消打印、保存已取得信息并执行关机策略 |
| PL 硬件状态机 | 视频/ROI 运算、缓存、总线握手、事件 FIFO、PWM、按键、看门狗 | 输出溢出/失锁等状态；指定保护条件触发时直接关 LED1/LED2，不等待 Linux 调度 |
| ESP32 服务状态机 | UART 会话、NFC、SD、音频、Wi-Fi/NTP、本地掉电准备 | 停止音频、禁止功放开启、停止文件访问和新作业，并上报状态；不承诺整机供电保持时间 |

PS 决定 LED2 十字投影的业务策略：默认测量开始关闭、结束后恢复；该策略启用时采集/分析期间禁止重开或临时更改策略。PL 执行输出并提供指定故障关断，ESP32 不控制这两路灯。

硬件保护优先于普通命令。PL 目前的 PFAIL/看门狗保护仅覆盖已接入的指定输出，不能宣称它会自动切断 TCA9555 控制的全部负载。系统恢复后由 PS 核对状态再恢复业务。

## 5. 实现优先级与资源约束

1. 先确认相机输入、帧号/时间戳、Linux 缓冲和显示通路，建立可比较的软件参考结果。
2. 优先实现一个目标 ROI＋一个背景 ROI 的 PL 跟踪链，先采用与当前 PS NCC/ZNCC 基准一致的计算；整数搜索先迁入，亚像素拟合初期保留 PS，验证后迁入 PL。
3. 在资源和帧率预算内扩展多测点。运算单元可按帧复用，不承诺所有 ROI 各占一套并行电路；最终算法选型以同输入误差、质量、耗时及综合结果决定。
4. PS 完成背景运动补偿、质量判定和物理标定。背景须是合适的参考；装在振动机架上的区域不自动等于静止背景，单点相减也不能普遍消除旋转/透视运动。
5. 双目深度用于空间标定及后续三维测量；视差不等于振动位移。运动放大/能量显示为辅助支路，不把增强后的图像回送定量跟踪。

队友工程当前集成版（去掉闲置 BM，加双目核＋DMA 和麦克风接收核）：13.5k LUT（76.7%）、slice 98.6%、41.5 个 BRAM36，WNS +0.462ns/WHS +0.007ns，位流尚未上板。slice 已基本用满：麦克风只保留接收与计时（抽取在 PS），并把双目 DMA 存储侧改 64 位、HP1 改 40MHz 省出互连资源才放下。显示增强链 160×90 另估约 22 个 BRAM36，与位移核接入前都需要再腾出 slice 和 BRAM；FFT、记录和界面继续留 PS。

## 6. 当前完成情况和验收

当前 PL 位移核尚未实现，Linux 的软件跟踪仍是运行基准，不能把以下目标分工写成已经完成的硬件加速成果。

| 模块 | 当前证据 | 尚未完成 |
|---|---|---|
| PS Linux 主程序 | 已 ARM 构建；AN5642 相机和自有 UI 已在板上运行；新增队友多点核、可拖动背景参考、停机基线，视频回放约 10.844Hz；保留单 ROI NCC/LK | 最新提交尚未再上板；A9 多点持续帧率、物理幅值标定、PL 位移接入和精确同步融合 |
| PL 载板控制 | carrier_ctrl 和测试平台行为仿真通过 | 与相机工程合并、Vivado 综合实现、完整时序和首板验证 |
| PL 显示增强 | Python/C++/RTL 在已测数据上逐位一致 | AXI 封装、资源/时序验证、相机接入与上板 |
| PL 位移核 | 累加核 `lk_accum` RTL（插值＋5 路乘加，整数 ZNCC 与 LK 亚像素共用）与 C++ 位精确模型在 16 组黄金向量上逐位一致（Icarus）；见 [测振算法推进](../05_验证资料/测振算法/README.md) | 整数搜索序列器、ROI 窗口装载、寄存器/DMA 接口、综合与上板；PS 侧仍逐遍完成亚像素标量更新 |
| PL 双目核 | Census＋SGM RTL/AXI 与模型有逐位验证；`team_bm_to_stereo.tcl` 已在队友 AN5642 工程实现并生成 40MHz 位流（HP1，核 0x43C20000、DMA 0x40400000），资源/时序见§5；PS 驱动已有 | 新位流上板、实拍棋盘格标定；不能把通用 HP2 脚本地址与此实际集成版混用 |
| 队友双摄/BM 工程 | 原包有位流、DCP 和报告；跟踪/FFT 在 ARM 裸机中 | 载板及 Linux 整合；完整时序约束、当前 XSA 与板端复测 |
| MP34DT01 声学输入 | 接收核 RTL 仿真、PS 抽取逐位一致、服务/分析/记录/界面及主机测试通过；队友工程与载板设计脚本已加入接收核 | 实物模块与线束波形、上板连续采集、A9 耗时、已知声源频率轴；没有实时录音成果 |

验收至少包括：同一输入下 PS 与 PL 位移/质量一致性；每帧耗时、测点数、CPU 占用、丢帧/失锁率；NFC/音频/SD/断线重连与掉电事件；标定后频率和幅值误差。不得只凭 FPGA 内存在某个 IP 宣称它参与了测振加速。

620rpm 约 10.33Hz 为用户给出的名义转速，不固定算法输出。新视频的视觉多点主频约 10.844Hz，内录声音包络约 10.84–10.86Hz（取决于声频带与方法），属于该片段的独立分析结果，不是 MP34DT01 采集成果。声学峰与转频可能存在谐波关系，需实测对照。提高 PL 时钟不提高相机采样率，也不消除曝光模糊/混叠。
